# 雪涼云 AI 绘画 Beta2 更新日志

发布日期：2026-06-28

版本标识：`2.6.0-beta2`

Beta2 是 2.6.0 独立 AI 绘画服务上线后的第一轮体验修正版。本次更新重点解决“能用但不好用”的问题：提示词生成更可靠、服务状态更透明、LoRA 和角色预设选择更直观、双角色模式支持单/双角色计费和更稳的默认策略，本机 Worker 也从调试页面进一步转向运维控制台。

本次更新仍保持原设计：云端后端是唯一业务入口，本机 `setu_ai_wife` 只作为主动轮询的 AI Worker；本机端口不需要公网暴露；图片继续通过云端后端写入 OSS。

## 一、版本重点

### 1. AI 绘图页面体验优化

- 绘图入口继续使用 `/dashboard/ai-draw`。
- 自然语言描述变为可选，不再强制填写。
- 用户只填写正向提示词，也可以直接生成图片。
- 自然语言生成提示词和正式生图流程拆开，生成出的正向/反向提示词可以继续编辑。
- 画幅预设调整为更适合 SDXL 动漫模型的常用尺寸：
  - 竖屏人像：`832x1216`
  - 横屏场景：`1216x832`
  - 大头照：`1024x1024`
  - 手机壁纸：`832x1472`
- 修复画幅选择、生成提示词按钮、角色卡片和注入 tags 区域的多处重叠问题。
- 生成按钮根据身份和模式显示实际消耗：
  - 单角色普通用户：50 积分。
  - 双角色普通用户：100 积分。
  - 管理员：免费。
- 前端显示 Beta 开放时间：每天 `08:30-22:30`。
- 管理员不受开放时间限制，但仍要求 Worker 在线。

### 2. 服务在线状态和队列可见性

- 新增 AI 服务状态展示，用户进入绘图页即可看到当前服务是否可用。
- 前端会轮询 `/ai/status`，展示 Worker 在线状态、开放时间和服务提示。
- 后端扩展队列统计字段：
  - `queuedCount`
  - `claimedCount`
  - `runningCount`
  - `uploadingCount`
  - `estimatedWaitSeconds`
  - `openStartTime`
  - `openEndTime`
  - `nextOpenTime`
- 新增任务状态 `UPLOADING`，用于区分“本机已出图，正在上传 OSS”和“还在 ComfyUI 生成中”。
- 后端增加任务超时处理：
  - `CLAIMED` 超时未运行会退回队列。
  - `RUNNING` / `UPLOADING` 超时会失败并自动退还积分。

### 3. Ollama 提示词生成改进

- 云端自然语言提示词生成改为走本机 Worker 的 Ollama，不再由云端直接生成。
- 后端新增提示词翻译任务表 `ai_prompt_translation_job`，用于排队、领取、回写提示词生成结果。
- Worker 调用本机 Ollama 时会结合本地提示词知识库。
- 新增本地知识库文件：`setu_ai_wife/config/prompt_knowledge.json`。
- 新增说明文档：`setu_ai_wife/docs/PROMPT_KNOWLEDGE.md`。
- 优化中文角色名翻译，减少把中文原文直接塞进英文 tag prompt 的情况。
- 移除默认强塞的通用质量词堆叠，避免反复出现：
  - `masterpiece`
  - `best quality`
  - `high quality`
  - `anime illustration`
  - `detailed eyes`
  - `clean lineart`
- Ollama 不可用或超时时，前端会显示明确错误，不会把失败伪装成正常翻译。

### 4. LoRA 和角色预设选择器升级

- LoRA 和角色预设不再只使用普通下拉框。
- 前端新增资产选择器组件：
  - 左侧目录树按类型和分类分组。
  - 右侧卡片展示显示名、预览图和摘要。
  - 点击卡片即可选择。
  - 点击详情可查看完整元信息。
- 支持的元信息包括：
  - 显示名
  - 文件名
  - 触发词
  - 推荐强度
  - 适配 checkpoint
  - 说明
  - 预览图
  - 分类
  - 分类类型
- LoRA 默认值始终为“不使用 LoRA”。
- 选择角色预设后，会自动注入角色 tags，不再要求用户必须手填正向提示词才能提交。
- “将注入的角色 tags”移动到卡片区域下方，避免挤乱角色预设卡片。
- checkpoint 文件名支持友好显示名，目前默认模型显示为“二次元动漫 WAI”。

### 6. 双角色模式 Beta 支持

新增双角色生成模式：

- 前端可在单角色 / 双角色之间切换。
- 双角色模式支持：
  - 角色 A 预设。
  - 角色 B 预设。
  - 第一 LoRA。
  - 第二 LoRA。
  - 第二角色 ID。
  - 可选角色布局参考。
- 后端新增 `generation_mode`，支持 `SINGLE` 和 `DUAL`。
- 后端新增第二角色相关字段：
  - `second_lora_name`
  - `second_lora_strength`
  - `second_character_id`
  - `character_mask_json`
- 双角色普通用户按两张图计费，即 100 积分。
- 管理员双角色仍免费。
- 双角色 prompt 会自动过滤 `1girl`、`solo` 等单角色 tags，降低双角色生成被单角色词污染的概率。
- Worker 默认降低双角色 LoRA 强度上限，减少两个角色特征互相污染。

### 7. 双角色手绘区域策略修正

早期 Beta2 试过区域 mask、inpaint 和区域 conditioning，但实际效果容易出现：

- 两个角色融合成一个角色。
- B 角色被擦掉。
- 左右两侧各自生成两个人。
- 多手、多脚增加。
- 手绘线条或遮罩思路干扰画面。

因此当前默认策略已调整为：

- `DUAL_CHARACTER_STRATEGY=auto`
- 不画区域时：普通双角色单次生成。
- 同时画出 A/B 区域时：只提取大致位置、上下左右和靠近关系，转成普通布局提示词。
- 默认不再使用 ComfyUI `ConditioningSetMask`。
- 默认不再使用二次 inpaint。

保留实验开关：

- `DUAL_CHARACTER_STRATEGY=mask-conditioning`
- `DUAL_CHARACTER_STRATEGY=inpaint`

但这两个只建议排查或实验，不建议作为普通用户默认方案。

### 8. 本机 Worker 控制台和健康检查

- 本机首页从“本机绘图工作台”调整为 Worker 控制台。
- 控制台展示：
  - ComfyUI 状态。
  - Ollama 状态。
  - 本机 FastAPI 状态。
  - 云端 API 配置状态。
  - Worker Token 配置状态。
  - 模型目录状态。
  - 默认 checkpoint 是否存在。
  - checkpoint / LoRA / VAE / 角色预设数量。
- 新增本机健康检查接口：

```text
GET /api/health
```

- 一键启动脚本支持 `-Restart`。
- 云端上传成功后默认清理本机临时图片，减少 `outputs/` 长期堆积。

## 二、后端更新

后端仓库：`setu_api_full`

### 1. 新增数据库迁移

新增：

- `V14__ai_prompt_translation_jobs.sql`
  - 新增 `ai_prompt_translation_job`。
  - 支持自然语言提示词翻译任务排队、Worker 领取、完成和失败回写。
- `V15__ai_generation_dual_character.sql`
  - 给 `ai_generation_job` 增加双角色字段。
  - 增加 `generation_mode` 索引。
- `V16__ai_generation_character_masks.sql`
  - 给 `ai_generation_job` 增加 `character_mask_json`。
  - 用于保存前端角色布局参考数据。

### 2. AI 服务状态接口

新增或扩展：

```text
GET /ai/status
```

返回内容包含：

- Worker 是否在线。
- 当前是否开放。
- 当前开放时间。
- 下次开放时间。
- 队列数量。
- 运行中数量。
- 上传中数量。
- 预计等待时间。
- 管理员可用性判断。

普通用户和 API Key 用户必须满足：

- 当前时间在 `08:30-22:30`。
- Worker 在线。

管理员和管理员名下 API Key 满足：

- Worker 在线即可使用。
- 不受 Beta 开放时间限制。

### 3. Worker 状态回写

新增：

```text
POST /ai-worker/jobs/{id}/uploading
```

用于 Worker 在本机生成完成、准备上传 OSS 前，把任务状态切换为 `UPLOADING`。

### 4. 双角色计费和权限

- 单角色普通用户：50 积分。
- 双角色普通用户：100 积分。
- API Key 按 Key owner 身份计费。
- 管理员和管理员名下 API Key 不扣积分。
- Worker 或系统失败仍会自动退款。

### 5. 失败信息优化

后端会把常见错误转换成更容易理解的提示：

- Worker 离线。
- ComfyUI 未启动。
- Ollama 超时。
- 模型不存在。
- LoRA 不存在。
- OSS 上传或权限错误。
- 任务超时。

## 四、本机 Worker 更新

本机仓库：`setu_ai_wife`

### 1. Ollama 翻译链路

- Worker 负责领取云端提示词翻译任务。
- 调用本机 Ollama 生成英文正向/反向提示词。
- 使用 `config/prompt_knowledge.json` 给 Ollama 提供角色名、作品名和别名上下文。
- 对 Ollama 返回结果做基本校验，发现正向提示词仍包含中文时会报错，提示重试。

### 2. 能力上报增强

Worker 上报能力时包含：

- checkpoint。
- LoRA。
- VAE。
- 角色预设。
- 角色预设 metadata。
- checkpoint metadata。
- LoRA metadata。

前端看到的是云端缓存后的能力信息，不直接访问本机。

### 3. 角色和模型元信息

维护位置：

- 角色预设：`setu_ai_wife/config/characters.json`
- LoRA 元信息：`setu_ai_wife/config/lora_metadata.json`
- checkpoint 元信息：`setu_ai_wife/config/checkpoint_metadata.json`
- 提示词知识库：`setu_ai_wife/config/prompt_knowledge.json`

### 4. 双角色生成策略

新增配置：

```dotenv
DUAL_CHARACTER_STRATEGY=auto
DUAL_LORA_STRENGTH_CAP=0.65
DUAL_MASK_CONDITIONING_STRENGTH=0.95
DUAL_INPAINT_DENOISE=0.62
DUAL_INPAINT_MASK_OVERLAP_RATIO=0.08
```

推荐保持：

```dotenv
DUAL_CHARACTER_STRATEGY=auto
```

当前默认策略不再把手绘区域当作真实遮罩，只把它转成布局提示，避免区域条件导致两个角色合并。

## 八、已知限制

- 双角色仍是 Beta 能力。两个角色 LoRA 同时加载时，基础 ComfyUI 节点无法做到真正的 LoRA 区域隔离，仍可能出现角色特征串味。
- 手绘 A/B 区域当前只作为布局参考，不是精准分割遮罩。
- 亲密互动、遮挡严重、上下叠放等构图仍依赖模型理解和 prompt 质量。
- 如果后续要继续提升双角色稳定性，需要接入 attention couple / regional LoRA 类自定义节点，或引入自动分割后的局部修复流程。
- Ollama 不会永久学习，本地知识库是每次请求前注入上下文，不会修改模型权重。
