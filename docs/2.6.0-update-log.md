# 雪涼云 2.6.0 更新日志

发布日期：2026-06-27

2.6.0 是一次以“独立 AI 绘画服务”为核心的大版本更新。本版本把本机 ComfyUI 出图能力接入云端业务体系：用户在云端前端提交任务，云端后端负责鉴权、扣积分、排队、OSS 存储、历史、广场和管理员审核，本机 `setu_ai_wife` 只作为主动轮询的 AI Worker 运行，不需要公网暴露本机端口。

同时，本版本也包含前后端性能优化、系统状态接口优化、AI 生图删除申请流程、前端交互优化和本机 Worker 一键启动能力。

## 一、核心新增：独立 AI 绘画服务

### 1. 云端业务入口

新增独立 AI 绘画业务域，不复用图片投稿审核表：

- 用户端接口挂载在 `/ai/**`，使用现有登录用户鉴权。
- API Key 接口挂载在 `/ai-api/**`，使用现有 API Key 鉴权，任务归属到 Key 所属用户。
- Worker 接口挂载在 `/ai-worker/**`，使用独立 `AI_WORKER_TOKEN`。
- 管理员接口挂载在 `/admin/ai/**`，使用现有管理员鉴权。

云端后端成为唯一业务入口，负责：

- 用户鉴权和 API Key 鉴权。
- 普通用户生图扣 50 积分。
- 管理员和管理员名下 API Key 免费生图，记录 0 积分调用。
- 任务排队、Worker 领取、运行状态回写。
- 生成图写入 OSS 私有路径。
- 用户历史、管理员总览、AI 广场、审核和下架。
- 用户删除申请和管理员直接删除。

### 2. 本机 Worker 模式

新增 `setu_ai_wife` 本机 AI Worker：

- 本机运行 ComfyUI、FastAPI 和 cloud worker。
- Worker 主动轮询云端任务，不要求云服务器访问本机。
- Worker 扫描本机模型能力并上报云端，包括 checkpoint、LoRA、VAE、角色预设。
- 前端读取云端 `/ai/capabilities`，因此用户能看到当前本机可用模型和 LoRA。
- 生成完成后由 Worker 回传图片，云端后端写入 OSS。
- 本机临时图片在上传成功后可自动清理，避免长期堆积垃圾文件。

本机一键启动脚本：

```powershell
cd C:\Users\rdpuser\Documents\setu_cd\setu_ai_wife
powershell -ExecutionPolicy Bypass -File scripts\start_cloud_all.ps1
```

### 3. OSS 图片流转

AI 生图不保存到云服务器本地磁盘，统一进入 OSS：

- 私有图：`ai/private/{userId}/{jobId}.png`
- 公开全年龄图：`ai/public/general/{jobId}.png`
- 公开 R18 图：`ai/public/r18/{jobId}.png`

访问规则：

- 用户只能查看自己的历史图，通过云端签名 URL 访问。
- 管理员可以查看所有 AI 生成图。
- 未审核、审核中、审核拒绝的图片不会进入 AI 广场。
- 审核通过后才进入对应的 AI 广场分类。
- 删除通过后会隐藏记录，并尝试清理私有图和公开图 OSS object。

OSS 权限补充：

- 原有投稿上传权限可继续复用。
- 为了支持 AI 生图删除，RAM 策略需要额外允许 `oss:DeleteObject`。
- 推荐至少覆盖 `ai/private/*` 和 `ai/public/*` 路径。

## 二、后端更新

后端仓库：`setu_api_full`

### 1. AI 生图核心表

新增 Flyway 迁移 `V12__ai_generation_service.sql`：

- `ai_generation_job`：记录生成任务、prompt、参数、状态、OSS key、积分扣费、公开状态。
- `ai_generation_review`：AI 绘画独立审核表，不复用投稿审核表。
- `ai_worker_node`：记录本机 Worker 心跳、版本和状态。
- `ai_worker_capability`：缓存 Worker 上报的 checkpoint、LoRA、VAE、角色预设能力。

新增 Flyway 迁移 `V13__ai_generation_delete_requests.sql`：

- 给 `ai_generation_job` 增加删除状态字段。
- 新增 `ai_generation_delete_request`，用于用户申请删除 AI 生图、管理员审核删除。

### 2. 用户端 AI 接口

新增：

- `POST /ai/generations`：创建 AI 生图任务。
- `GET /ai/generations`：查看自己的 AI 生图历史。
- `GET /ai/generations/{id}`：查看自己的任务详情。
- `GET /ai/generations/{id}/image-url`：获取自己的图片签名 URL。
- `POST /ai/generations/{id}/review`：提交 AI 广场审核，可选择 `GENERAL` 或 `R18`。
- `POST /ai/generations/{id}/delete-request`：申请删除自己的 AI 生图。
- `GET /ai/delete-requests`：查看自己的删除申请。
- `GET /ai/delete-requests/{id}`：查看自己的删除申请详情。
- `GET /ai/capabilities`：读取当前 Worker 上报的模型、LoRA、角色能力。
- `GET /ai/square`：读取审核通过的 AI 广场。

### 3. API Key AI 接口

新增：

- `POST /ai-api/generations`
- `GET /ai-api/generations/{id}`
- `GET /ai-api/generations/{id}/image-url`

规则：

- 普通 API Key 生图扣 Key 所属用户 50 积分。
- 管理员用户创建的 API Key 生图不扣积分。
- API Key 生图和登录用户生图进入同一套任务队列。

### 4. Worker 接口

新增：

- `POST /ai-worker/heartbeat`
- `POST /ai-worker/capabilities`
- `POST /ai-worker/jobs/claim`
- `POST /ai-worker/jobs/{id}/running`
- `POST /ai-worker/jobs/{id}/upload-url`
- `POST /ai-worker/jobs/{id}/complete`
- `POST /ai-worker/jobs/{id}/fail`

当前上传模式为 `CLOUD_COMPLETE_BASE64`：

- Worker 读取本机临时图片 bytes。
- Worker 调用云端 complete 接口。
- 云端后端通过已有 `StorageService` 写入 OSS。
- 云服务器本地不落盘保存图片。

### 5. 管理员 AI 接口

新增：

- `GET /admin/ai/generations`：查看所有用户 AI 生成记录。
- `GET /admin/ai/reviews`：查看 AI 广场审核队列。
- `POST /admin/ai/reviews/{id}/approve`：审核通过并发布到 AI 广场。
- `POST /admin/ai/reviews/{id}/reject`：拒绝审核。
- `POST /admin/ai/generations/{id}/unpublish`：下架公开图。
- `GET /admin/ai/delete-requests`：查看 AI 删除申请队列。
- `GET /admin/ai/delete-requests/{id}`：查看删除申请详情。
- `POST /admin/ai/delete-requests/{id}/approve`：通过用户删除申请。
- `POST /admin/ai/delete-requests/{id}/reject`：拒绝用户删除申请。
- `POST /admin/ai/generations/{id}/delete`：管理员直接删除 AI 生图。

### 6. 积分规则

- 普通登录用户创建任务时立即扣 50 积分。
- 普通 API Key 创建任务时扣 Key owner 的 50 积分。
- 管理员和管理员名下 API Key 不扣积分。
- Worker 或系统失败导致最终无法出图时，自动退还已扣积分。
- 审核拒绝、用户未提交审核、用户不满意结果不退积分。

### 7. 删除规则

- 用户不能直接删除已生成图片，需要提交删除申请。
- 管理员可审核通过或拒绝删除申请。
- 管理员也可以在生成记录中直接删除任意 AI 生图。
- 删除后任务会从用户历史、管理员列表、AI 广场、Worker 待领取任务中隐藏。
- 删除时会尝试清理 OSS 私有图和公开图。
- OSS 删除失败不会阻断数据库删除流程，但会写入后端日志，便于排查权限问题。

### 8. 性能和稳定性优化

2.6.0 同时包含后端性能优化迁移 `V11__xueliang_2_6_0_performance.sql`：

- 给 `user_collection` 增加 `item_count`。
- 给 `user_collection` 增加 `share_hot_score`。
- 回填收藏夹图片数量和热度分。
- 给公开收藏夹排序和筛选增加索引。
- 回填 `api_request_log.endpoint_group`。
- 优化部分鉴权摘要、API Key 摘要和状态接口相关缓存。
- 优化图片投稿发布流程和后台处理线程配置。

## 三、前端更新

前端仓库：`setu_cloud`

### 1. 用户端新增页面

新增用户端 AI 页面：

- `/dashboard/ai-draw`：AI 绘图。
- `/dashboard/ai-history`：我的 AI 生图历史。
- `/dashboard/ai-square`：AI 广场。

### 2. AI 绘图页面

新增能力：

- 支持自然语言描述。
- 支持调用本地 LLM 将中文描述转换为正向/反向提示词。
- 支持正向提示词和反向提示词生成后继续编辑。
- 支持只填写正向/反向提示词直接生图，不强制填写自然语言描述。
- 支持 checkpoint 选择。
- 支持 LoRA 选择，也支持“无 LoRA”模式。
- 支持角色预设选择。
- 支持 LoRA 强度配置。
- 支持 steps、CFG、seed 等高级参数。
- 默认展示 50 积分消耗提示。
- 管理员账号显示免费生图。

新增尺寸预设：

- 竖屏：`832x1216`
- 横屏：`1216x832`
- 大头照：`1024x1024`

### 3. 我的 AI 历史

新增能力：

- 仅展示当前登录用户自己的 AI 生成记录。
- 支持按任务状态筛选。
- 支持查看原图。
- 支持复用 prompt 和生成参数。
- 支持提交 AI 广场审核。
- 审核分类支持 `全年龄` 和 `R18`。
- 支持提交删除申请。
- 删除申请状态会显示在历史卡片上。

状态文案优化：

- 原来“已完成/失败”旁边的第二个“未提交”容易被误解。
- 现在第二状态明确显示为“广场审核：未提交/待审核/已公开/已拒绝”。
- 失败图片不再显示广场审核状态。

### 4. AI 广场

新增能力：

- 展示审核通过且公开的 AI 生图。
- 支持全年龄、R18、全部分类切换。
- 未审核、审核拒绝、已下架、已删除的图片不会进入广场。

### 5. 管理员后台新增页面

新增管理员页面：

- `/admin/ai-generations`：AI 生成记录。
- `/admin/ai-reviews`：AI 审核队列。
- `/admin/ai-delete-requests`：AI 删除申请。

管理员生成记录页支持：

- 查看全部用户 AI 生图。
- 按用户 ID、任务状态、审核状态筛选。
- 查看图片、prompt、尺寸、错误原因。
- 下架已公开图片。
- 直接删除 AI 生图。

管理员审核队列支持：

- 查看待审核 AI 图片。
- 按审核状态和分类筛选。
- 通过后发布到 AI 广场。
- 拒绝时填写原因。

管理员删除申请支持：

- 查看用户提交的 AI 删除申请。
- 通过删除申请。
- 拒绝删除申请并填写原因。
- 通过后隐藏记录并清理 OSS 图片。

### 6. 前端性能和体验优化

2.6.0 还包含一批前端性能和体验优化：

- 前端版本号更新到 `2.6.0`。
- 优化部分页面布局和移动端体验。
- 优化音乐播放器相关组件的渲染和交互。
- 优化系统状态页展示。
- 优化公开收藏夹和个人主页部分加载体验。
- 增加前端 Mock 支持，便于本地开发和调试。

## 四、本机 AI Worker 更新

本机项目：`setu_ai_wife`

### 1. 本机服务能力

新增本机 FastAPI 服务：

- 默认访问地址：`http://127.0.0.1:7861`
- 默认 ComfyUI 地址：`http://127.0.0.1:8188`
- 支持本地网页输入 prompt 出图。
- 支持 SQLite 保存本机任务历史。
- 支持 Ollama + Qwen 进行中文 prompt 翻译。
- Ollama 不可用时可退化为模板拼接模式。

### 2. ComfyUI 集成

支持：

- ComfyUI Portable Windows。
- SDXL/动漫模型 workflow。
- 动态替换 prompt、negative prompt、seed、尺寸、checkpoint、LoRA。
- 默认 checkpoint 配置。
- LoRA 文件扫描。
- 角色 LoRA 预设。

### 3. 云端 Worker 模式

新增 cloud worker 模式：

- 扫描本机模型目录。
- 上报 checkpoint、LoRA、VAE、角色预设。
- 定时上报心跳。
- 轮询云端任务。
- 领取任务后调用本机 FastAPI 生成图片。
- 成功后回传云端。
- 失败后回写错误并触发云端退积分。

### 4. 一键启动脚本

新增：

- `scripts/start_cloud_all.ps1`
- `scripts/start_service.ps1`
- `scripts/start_cloud_worker.ps1`

`start_cloud_all.ps1` 会按顺序启动：

1. ComfyUI
2. 本机 FastAPI 服务
3. cloud worker

日志写入 `logs/`，便于排查。

### 5. 本机文件清理

新增自动清理能力：

- Worker 在云端 complete 成功后清理本机 `outputs` 下对应临时图。
- 本机服务复制 ComfyUI 输出后清理 ComfyUI `output/local_ai_drawing` 下的原始输出。
- 可通过 `.env` 中 `AI_WORKER_CLEANUP_OUTPUTS=true` 开启 Worker 输出清理。

## 五、配置变更

### 1. 后端环境变量

生产后端需要确认：

```dotenv
AI_WORKER_TOKEN=你的-worker-token
AI_GENERATION_COST=50
AI_PREVIEW_URL_TTL_SECONDS=900
AI_MAX_COMPLETE_IMAGE_BYTES=20971520
```

说明：

- `AI_WORKER_TOKEN` 必须和本机 `setu_ai_wife/.env` 中的 `AI_WORKER_TOKEN` 一致。
- OSS endpoint、bucket、AccessKey 等继续使用原有后端 OSS 配置。
- 如需删除 AI 生图，OSS RAM 策略需要包含 `oss:DeleteObject`。

### 2. 本机 Worker 环境变量

本机 `setu_ai_wife/.env` 需要确认：

```dotenv
LOCAL_AI_URL=http://127.0.0.1:7861
CLOUD_API_URL=https://api.yukiryou.icu
AI_WORKER_TOKEN=与后端一致的-token
AI_WORKER_ID=local-comfyui-worker
AI_WORKER_NAME=Local ComfyUI Worker
AI_WORKER_VERSION=0.1.0
AI_WORKER_POLL_SECONDS=5
AI_WORKER_CAPABILITY_REPORT_SECONDS=60
AI_WORKER_CLEANUP_OUTPUTS=true
```

### 3. OSS RAM 权限

AI 生图上传需要：

- `oss:PutObject`
- `oss:GetObject`

AI 生图删除还需要：

- `oss:DeleteObject`

建议资源范围：

```json
[
  "acs:oss:*:*:setu-pending/ai/private/*",
  "acs:oss:*:*:setu-pending/ai/public/*"
]
```

如果公开图使用其他 bucket，也需要给对应 bucket 的 `ai/public/*` 加上权限。

## 六、部署和升级步骤

### 1. 后端

1. 拉取 `setu_api_full` 最新代码。
2. 确认后端 `.env` 或生产环境变量包含 `AI_WORKER_TOKEN`。
3. 确认 OSS RAM 策略具备 AI 路径的上传、读取、删除权限。
4. 重新构建并部署后端。
5. 启动后确认 Flyway 已执行：
   - `V11__xueliang_2_6_0_performance.sql`
   - `V12__ai_generation_service.sql`
   - `V13__ai_generation_delete_requests.sql`

### 2. 前端

1. 拉取 `setu_cloud` 最新代码。
2. 重新安装依赖或确认依赖已同步。
3. 执行生产构建。
4. 发布前端静态资源。
5. 管理员后台确认出现：
   - AI 生成记录
   - AI 审核队列
   - AI 删除申请

### 3. 本机 Worker

1. 拉取 `setu_ai_wife` 最新代码。
2. 确认 `.env` 中 `CLOUD_API_URL` 指向云端后端。
3. 确认 `AI_WORKER_TOKEN` 与云端后端一致。
4. 确认模型、LoRA 已放入 ComfyUI 对应目录。
5. 执行一键启动脚本。
6. 在前端 `/dashboard/ai-draw` 点击刷新模型，确认能看到本机 checkpoint 和 LoRA。
